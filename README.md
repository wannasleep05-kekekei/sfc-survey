# sfc-search-tools

SFC の研究会・卒プロ向け、先行研究サーベイ CLI。

**慶應のシステムに機械的なアクセスを一切行いません。** アカウント情報も扱いません。事前の許諾申請も不要です。

---

## 何をするツールか

先行研究サーベイのボトルネックは「PDF を集める速度」ではなく「**何を読むべきか見極める作業**」です。このツールはそこを加速します。

```
search    →  数百件のメタデータを機械で集める（公開APIのみ）
export    →  絞り込み用に書き出す
holdings  →  慶應の所蔵確認URLを出す（人がブラウザで確認）
open      →  絞った20〜30本を人間がブラウザで開く
ill       →  残りは文献複写依頼へ
```

## セットアップ

**プログラミングが初めての方は [はじめかた（SETUP.md）](SETUP.md) を読んでください。**
GitHub の知識も git も不要で、ZIP をダウンロードするところから順に説明しています。

以下は慣れている方向けです。Python 3.8 以上、外部依存はありません。

```bash
git clone https://github.com/wannasleep05-kekekei/sfc-survey
cd sfc-survey
./sfc-search config --contact yourname@keio.jp
```

連絡先は User-Agent に載ります。何か問題があったときに、遮断ではなくあなたにメールが来るようにするためです。OpenAlex と Crossref はメールアドレス付きのリクエストを優先レーン（polite pool）で処理するので、速度面でも得をします。

## 使い方(Claude Codeを持っている人は読み飛ばしてok)

### 横断検索

```bash
sfc-search search "視覚障害 情報アクセシビリティ" --count 100
```

OpenAlex・Crossref・CiNii・NDLサーチを叩いて、DOI とタイトルで名寄せして統合します。

```bash
--books                             # 書籍に絞る（NDL の category=図書）
--loose                             # NDL を全文検索に（再現率↑ 精度↓）
--source openalex --source ndl      # ソースを指定
--since 2015 --until 2024           # 年で絞る
--sort cited                        # 被引用数順
--verbose                           # 抄録も表示
```

### 引用チェイニング

サーベイの王道は「重要な1本を見つけて引用の前後に辿る」です。

```bash
sfc-search refs 10.1145/3234695        # この論文が引用している文献
sfc-search cited-by 10.1145/3234695    # この論文を引用している文献
sfc-search snowball 10.1145/3234695    # 前後1段をまとめて
```

既定は被引用数順です。`--sort new` で新しい順、`--sort old` で古い順。被引用数順だと分野の古典が上位に来る反面、最新の研究が下に沈むので、動向を見たいときは `--sort new` と併用してください。

### 慶應の所蔵確認

```bash
sfc-search holdings                    # 確認用URLの一覧
sfc-search holdings --open 1-10        # 10件をブラウザで開く
sfc-search hold 3 --library SFC --call 369.27@Y16
sfc-search hold 4 --none
```

`holdings` は **KOSMOS の検索 URL を組み立てるだけ**で、リクエストは送りません。実際のアクセスはあなたがブラウザで行います。結果を `hold` で記録しておくと `ill` の精度が上がります。

論文は掲載誌名、書籍は書名で照会します。誌名の長音記号のゆれ（`ノ-マライゼ-ション` → `ノーマライゼーション`）は自動で正規化し、同じ雑誌の論文はまとめて1件の照会にします。

出力は「慶應に無かったとき」まで面倒を見ます。1件ごとに次が並びます。

- 論文なら**必要な巻号ページ**（例: `47(5), 582-603 (2024)`）
- 図書なら**国内所蔵**（CiNii Books の NCID ページ。どの大学が持っているか）
- それでも無い場合の **ILL の窓口**（論文は複写、図書は貸借で URL が違う）

### 雑誌は「所蔵あり」で終わりにしないでください

読めるかどうかは誌名がヒットするかではなく、雑誌レコードの「オンラインで見る」に出る**提供元ごとの収録範囲**で決まります。実測（2026-07-27）した例です。

| 提供元 | Popular Music and Society の範囲 |
|---|---|
| EBSCOhost Academic Search Complete | 1996/06 以降。**直近1年は利用不可** |
| Taylor & Francis Online Archive | 1971–1996 のみ |

つまり「オンラインで利用可」と表示されていても、必要な巻号がムービングウォールの内側なら読めません。`holdings` が併記する巻号と、この収録範囲を必ず突き合わせてください。

### KOSMOS の検索は URL からは制御できません

実測（2026-07-26）で確認した挙動です。

| 投げたもの | 結果 |
|---|---|
| `/discovery/search` に `title,contains,ノーマライゼーション` | 27件、すべて無関係 |
| `/discovery/jsearch` に `any,contains,ノーマライゼーション` | 66,725件、図書やビデオが並ぶ |

Primo は URL 経由のクエリを極端に緩く照合します。**したがって、このツールが所蔵の有無を自動判定することはできません。**

`holdings` の役割は「正しい検索語を用意して、それが検索欄に入った状態で KOSMOS を開くところまで」です。開いたら検索ボタンを押し直してください。自動表示される結果は当てになりません。

検索語だけ欲しい場合は `sfc-search holdings --terms` でコピペ用に出力できます。

30本の確認で 10〜15 分ほどを見てください。

### 絞り込み

```bash
sfc-search export --format md --with-abstract --out survey.md
```

メタデータ＋抄録を書き出します。これを読んで精読すべきものを選びます。分類・仕分けを LLM に手伝わせる場合もこのファイルを渡してください。

### 本文の入手

```bash
sfc-search fetch --limit 30      # OA本文のみ自動取得
sfc-search open 3 7 12           # 残りをブラウザで開く
sfc-search ill                   # 複写（論文）と貸借（図書）に分けて依頼形式で出力
```

`fetch` は2段構えで OA 本文を探します。まず Unpaywall、駄目なら CiNii / NDL が返した**機関リポジトリ・J-STAGE の書誌ページ**を見て本文 PDF を拾います。

2段目が必要な理由は、Unpaywall が JaLC DOI と国内リポジトリをほとんどカバーしていないからです。実測（2026-07-27）では、誰でもダウンロードできる東京大学の博士論文（全282頁）も立教大学リポジトリの紀要論文も、Unpaywall 経由では「OA でない」と判定されました。**「取れなかった」を「読めない」と読み替えないでください。**

リポジトリは本文・要旨・審査要旨を同じページに並べるので、ファイル名から本文を選びます（要旨を本文と取り違えないため）。慶應が契約している有料フルテキストには触れません。

### 書籍の目次

```bash
sfc-search toc 3                 # 直近検索の3番
sfc-search toc 9781501339318     # ISBN でも DOI でも
```

Crossref に章 DOI が登録されていれば、章題とページ範囲が取れます。**和書はほぼ登録が無いので空になります。**空だったときは目次を推測せず「未確認」として扱ってください。

### 確認範囲を記録する

```bash
sfc-search verified 2 --level fulltext --note "第5章3節のみ"
sfc-search verified 3 --level toc --note "出版社の目次まで"
```

`biblio`（書誌のみ）/ `toc`（目次）/ `abstract`（抄録）/ `partial`（本文の一部）/ `fulltext`（本文読了）。`export --format md` の「確認範囲」に出ます。記録していないものは `**未記録**` と表示されるので、報告前に埋まっているか確認できます。

書誌だけ見た文献を、読んだかのように書かないための仕組みです。

## Claude Code に任せる

コマンドを覚えなくても、日本語で頼めば検索から絞り込みまで任せられます。導入は [SETUP.md](SETUP.md) を参照してください。`CLAUDE.md` を自動で読むので、やってはいけないことは指示しなくても守られます。

実際に一通り使って有効だった指示をテンプレートにしました。【】を埋めて貼り付けてください。

### ゼロから先行研究を探す

```
【sfc-survey-main フォルダのパス】 のツールを使って先行研究を探して。

■ テーマ
【調べたいこと。1〜2文。分野も書く】

■ 何に使うか
【卒論の第○章／研究会の発表／レビュー のどれか】

■ 読める言語
【日本語のみ／日本語＋英語 など】
※探す範囲は絞らないこと。読めない言語の文献も、効くなら挙げる。
　その場合は要旨と、なぜ効くのかを日本語で説明すること

■ 欲しいもの
・まず【20】件ほど集めて、そこから読むべき【5】件に絞って
・中核になりそうな論文が見つかったら snowball で引用を辿ること
　（キーワード検索では出てこない文献が出る）
・絞った各件について次を書く：
  - なぜ読むべきか（1〜2文）
  - 入手方法（OAならURL／慶應の所蔵確認ならKOSMOSのURL／慶應に無ければ国内所蔵／それも無ければILL）
    ・そのリンクを開くと何が表示されるか（本文／雑誌のレコード／書誌だけ）まで書く
    ・本文に届くまでにあと何が必要かを1行で書く
    ・OAでないものは「OAではない」と明記する。推測でOA扱いにしない
  - 中身をどこまで確認したか（書誌のみ／目次／抄録／本文の一部／本文読了）

■ 守ってほしいこと
・私が打つコマンドは書かない。ツール操作はそちらで完結させ、結果だけ渡す
・図書を候補から外さない。「今すぐ本文が読めるか」を選定基準にしない
・本文が取得できなかったときは、タイトルから内容を推測せず「未確認」と書く
```

### 指摘された穴を埋める

指導教員や講評で「この根拠は弱い」と言われたときに使います。指摘文は**要約せずそのまま貼ってください。** 一つの指摘に複数の論点が含まれていることが多く、要約すると分解できなくなります。

```
添付の文章について、【sfc-survey-main フォルダのパス】 のツールで文献を探して。

■ 状況
・テーマ　　：【　　】
・埋めたい穴：【指摘された内容を、要約せずそのまま貼る】
・使う場所　：【第○章の、どの主張の根拠にしたいか】
・読める言語：【日本語のみ／日本語＋英語 など】
　※探す範囲は絞らないこと。読めない言語の文献も、効くなら挙げる。
　　その場合は要旨と、なぜ効くのかを日本語で説明すること

■ 欲しいもの
・【3】件
・各文献について次を書く：
  - なぜその穴に効くのか（1〜2文）
  - 入手方法（OAならURL／慶應の所蔵確認ならKOSMOSのURL／慶應に無ければ国内所蔵／それも無ければILL）
    ・そのリンクを開くと何が表示されるか（本文／雑誌のレコード／書誌だけ）まで書く
    ・本文に届くまでにあと何が必要かを1行で書く
    ・OAでないものは「OAではない」と明記する。推測でOA扱いにしない
  - 中身をどこまで確認したか（書誌のみ／目次／抄録／本文の一部／本文読了）

■ 守ってほしいこと
・先に添付の文章を読んでから探す
・私が打つコマンドは書かない。ツール操作はそちらで完結させ、結果だけ渡す
・図書を候補から外さない。「今すぐ本文が読めるか」を選定基準にしない
・本文が取得できなかったときは、タイトルから内容を推測せず「未確認」と書く
・論旨に都合よく解釈しない。合わない文献は「合わない」と言う
```

フォルダの中で Claude Code を起動しているなら、パスの代わりに「このフォルダ」で通じます。人に渡すときはパスを書いた形の方が確実です。

このテンプレートに書いた3点（効く理由／入手方法／確認範囲）は、ツール側の出力がそのまま対応しています。`holdings` が慶應→国内所蔵→ILL の順に導線を出し、`verified` が確認範囲を保持し、`export --format md` が両方を並べて書き出します。したがって「入手方法が KOSMOS の URL だけで、慶應に無いと分かった時点で行き止まり」という報告にはならないはずです。なっていたら、そこはツールの不足です。

入手方法に3行足してあるのは、KOSMOS の所蔵検索が**雑誌単位**だからです。論文の入手先として KOSMOS の URL を渡されても、開いて出てくるのは雑誌のレコードであって論文ではありません。そこから必要な巻号が提供元の収録範囲に入っているかを突き合わせる作業が残ります（前掲のムービングウォールの例を参照）。この一段を書かせないと、「リンクを開いたのに論文が無い」という報告になります。

### 調査そのものを任せる

上の2つは「何を探すか」が決まっている場合です。まだ分野の見取り図がなく、どこから手を付けるか分からない段階では、調査全体を任せて**ドラフト**を作らせる方が早いことがあります。

出てくるものは下書きであって調査結果ではありません。**必ず後述の注記まで読んでください。**

```
【sfc-survey-main フォルダのパス】 のツールで、以下のテーマの文献調査をして、
ドラフトを作って。

■ テーマ
【調べたいこと。3〜4文で、背景と問いを書く】

■ 射程
・時期：【2000年以降 など。こだわらないなら「不問」】
・言語：【日本語のみ／日英both など】
・分野：【社会学・音楽学 など。分からなければ「不明」でよい】

■ 進め方
・検索語を変えて複数回検索し、母集団を広く取ること
・中核になりそうな文献は snowball で引用の前後を辿ること
・集めたものを論点ごとにグループ分けし、各グループに見出しを付けること
・グループ間で対立する主張があれば、対立として示すこと
・当たらなかった論点があれば「この論点は見つからなかった」と書くこと

■ 出力
・survey.md に書き出したうえで、要点を会話でも説明して
・各文献に、確認した深さ（書誌のみ／目次／抄録／本文読了）を必ず付けること
・各文献に入手方法（OAならURL／慶應の所蔵確認ならKOSMOSのURL／慶應に無ければ国内所蔵／それも無ければILL）を付けること
　- そのリンクを開くと何が表示されるか（本文／雑誌のレコード／書誌だけ）まで書く
　- 本文に届くまでにあと何が必要かを1行で書く
　- OAでないものは「OAではない」と明記する。推測でOA扱いにしない
・私が打つコマンドは書かない

■ 守ってほしいこと
・「網羅した」と言わない。取りこぼしの可能性がある方向を最後に挙げること
・本文を読めていないものを、読んだかのように書かない
・私の仮説に都合よく解釈しない。反証になる文献はむしろ優先して挙げること
```

#### ドラフトの扱いについて

**この出力を、そのまま提出物の根拠にはできません。** 用途は「どこから読み始めるか」の当たりを付けることに限られます。

- **引用する文献は、必ず自分で本文を読んでください。** 抄録と目次から書かれた要約は、引用の根拠になりません。読んでいない文献を引用することは、ツールを使ったかどうかに関係なく避けるべきことです
- **書誌情報は原典で確認してください。** 上流のメタデータには誤りが混ざります（日本語論文に海外出版社の DOI が付く、掲載誌名が別分野のものになる、など実例があります）
- **網羅性は保証されません。** 検索語の選び方で結果は大きく変わります。ドラフトに出てこなかったことは、存在しないことを意味しません
- **所蔵の有無は自動判定できません。** KOSMOS の仕様上不可能です。最終的な確認は人がブラウザで行う必要があります

見取り図を作るところまでが機械の仕事で、そこから先は人の作業です。ドラフトを起点に、自分で読み、自分で確かめてください。

### 制約の理由

飾りではなく、どれも実際に失敗して足したものです。

| 指示 | 理由 |
|---|---|
| 私が打つコマンドは書かない | 出力にコマンドが載ると、OS やシェルの差（Mac の `python3`、PowerShell で `&&` が使えない等）が問題になります。入手方法さえ書かせれば、手で打つ場面は残りません |
| 図書を候補から外さない | 「本文が今すぐ読めるか」で絞ると図書が全滅します。日本語の人文・社会科学では、中心的な仕事が図書にあることが珍しくありません |
| 推測せず「未確認」と書く | OA でも読めない PDF があります。J-STAGE のスキャン画像（テキスト層なし）、リポジトリ側のフォント破損など。タイトルと抄録だけで中身を推測できてしまうので、明示的に禁じます |
| 都合よく解釈しない | 手持ちの論旨に沿う文献ばかり並ぶと、反証が見えなくなります |

### よくある追加指定

**本文まで確認させたい場合**（そのまま追記）

```
・本文まで読み通せたものを最低【1】件は含めること。
　残りは書誌・目次・抄録どまりでよいが、どこまで確認したかを明記すること。
```

「本文を読めたものだけに絞る」は勧めません。図書が全て落ちるうえ、OA でも PDF が壊れていることがあり、残る件数が極端に減ります。

**読めなかったものを追いたい場合**

```
・本文が読めなかったものについては、書評・紹介記事・目次など
　二次情報で内容を確認し、その出所を明記すること。
```

日本語文献では、本文が読めなくても目次や書評から内容を詰められることが多く、こちらの方が歩留まりが良いです。

## 意図的に実装していない機能

| 機能 | 理由 |
|---|---|
| 慶應アカウントでのログイン | パスワードの平文保管と MFA の自動承認は、情報システム利用規程 第4条③④に抵触します（認証情報を一切扱わない設計です） |
| 契約フルテキストの取得 | 出版社ライセンスの systematic download 禁止条項に違反します。検知されると**大学全体**のアクセスが停止します（第4条⑨） |
| KOSMOS からの書誌自動取得 | `primaws/rest/pub/pnxs` は無認証で応答しますが、公開 API として提供されているものではありません。無認証で叩けることと、叩いてよいことは別です |
| 並列リクエスト | サーバへの負荷集中を避けるため |
| Google Scholar のスクレイピング | 公式 API がなく ToS で禁止されています（第4条⑪）。OpenAlex が上位互換です |
| User-Agent の偽装 | 虚偽の申告です（第4条⑪） |

これらは「今は作っていない」ではなく「作らない」機能です。Pull Request でも受け付けません。

契約フルテキストが必要な場合は `sfc-search open` でブラウザから正規にアクセスするか、`sfc-search ill` で文献複写依頼を出してください。大量のテキストを計量分析（TDM）に使いたい場合は、出版社の TDM 窓口を通す必要があります。メディアセンターに相談してください。

| [Crossref](https://www.crossref.org) | DOI 書誌 | API（1.0秒間隔） |
| [CiNii Research](https://cir.nii.ac.jp) | 日本語論文 | API（2.0秒間隔） |
| [NDLサーチ](https://ndlsearch.ndl.go.jp) | 日本語書籍 | API（2.0秒間隔・書名検索） |
| [Unpaywall](https://unpaywall.org) | OA 判定 | API（1.0秒間隔） |
| KOSMOS | 慶應所蔵の確認 | **URL生成のみ・リクエストなし** |

間隔はホストごとに強制され、呼び出し側から短縮できません。並列実行はしません。

本ツールは国立国会図書館サーチの API を利用しています。

NDLサーチについて実機で確認した挙動（2026-07-26）:

- `mediatype` パラメータは常に0件を返すため使用していません。書籍の絞り込みは
  `category` を見てクライアント側で行っています。
- 既定では書名検索（`title=`）を使います。全文検索（`any=`）は再現率が高い反面
  精度が低く、無関係な紀要などが上位に来るため `--loose` 指定時のみ使います。
- 並び順は関連度ではなく資料名の五十音順です。`--books` では絞り込みで減る分を
  見込んで多めに取得しています。
